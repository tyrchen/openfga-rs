# Key decisions

Each decision may be revisited only when its trigger occurs and the replacement preserves the PRD and verification gates.

| KD-030 | Commit tuple pairs, one packed logical change batch, and a conditional per-store change HEAD in one DynamoDB transaction; cap a request at 49 tuple mutations and enforce item/transaction byte budgets before dispatch. | KD-031 | Support one writable AWS Region initially and implement `HigherConsistency` with strongly consistent base-table reads; do not claim global-table semantics, DAX support, or multi-Region writes. | Global tables with last-writer-wins reconciliation; DAX; eventual GSI reads presented as higher consistency. | [DynamoDB design](17-dynamodb-storage-design.md), [storage](13-storage-design.md) | A separately designed and chaos-tested multi-Region conflict/consistency contract is accepted. |
| KD-032 | Preserve the existing versioned persistence codec and store large models/assertions as immutable bounded chunks behind staged manifests; publish models by a small manifest commit, replace assertions through an atomic generation HEAD, and reclaim unreachable chunks through a durable sharded cleanup directory. ## Rejected alternatives

- A monolithic `core` crate: encourages cycles and lets transport/storage types leak into semantics.
- A giant datastore mock interface: weakens interface segregation and makes algorithm tests brittle.
- CEL through C++ FFI by default: adds unsafe/native supply-chain surface contrary to project policy.
- Blind port of upstream adaptive raw-pointer atomics: unsafe and premature.
- Treating errors as deny: hides outages and changes union/intersection semantics.
- Running ListObjects by scanning every object and calling Check: correct only at unacceptable, unbounded cost.
- A GSI as the authoritative reverse-tuple index: GSI reads cannot be strongly consistent, so it cannot satisfy the existing higher-consistency contract.
- Rustack as the only DynamoDB release oracle: its current transaction provider does not model AWS idempotency or rollback-after-apply-failure exactly.
